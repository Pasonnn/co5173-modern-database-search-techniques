MASTER ARCHITECTURAL COMPARISON: CASSANDRA (LSM) VS. ELASTICSEARCH (INVERTED INDEX)
=========================================================================================================
Dimension                    | Apache Cassandra (LSM-Tree)          | Elasticsearch (Inverted Index)      
---------------------------------------------------------------------------------------------------------
Core Workload Target         | High-throughput append ingestion     | Multi-attribute lexical search      
Primary Data Layout          | MemTable + Immutable SSTables        | Term Dictionary (FST) + Postings    
Write Complexity             | O(1) sequential append to RAM        | O(W) tokenization + list appends    
Search Mechanics             | Bloom Filter -> Sparse Fence Index   | Posting List Intersect + BM25       
RUM Trade-off: Read Amp      | Higher (multi-SSTable lookup)        | Very Low for text (O(1) term hop)   
RUM Trade-off: Update Amp    | Minimal (no in-place random writes)  | Higher (segment merges & rewrites)  
RUM Trade-off: Memory Amp    | Low (~150 B/key with Bloom Filter)   | Moderate-High (terms + doc lengths) 
Empirical Ingest Throughput  | 52339 keys/s                         | 74028 docs/s                        
Empirical Read / Query       | 11.93 µs point lookup                | 174.68 µs BM25 search
